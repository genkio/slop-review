[English](./README.md) · [简体中文](./README.zh.md) · **日本語**

あなたとあなたの LLM のためのローカル PR レビューループ。任意の git リポジトリで実行できます。差分にインラインコメントを残し、同梱のスキルを通じてそのスレッドをレビュアーまたはレビュイーとして振る舞う LLM (Claude Code、Cursor、Codex など) に引き渡します。コメントは `<repo>/.reviews/` 配下の JSON ファイルなので、クリップボードでの受け渡しも、エージェントループのためにサーバーを動かし続ける必要もありません。

差分ページは 1 枚。ブランチ全体の差分、ローカルの作業コピー差分、あるいは任意の単一コミットを選べます。スレッドと LLM が生成したブランチ概要は、どちらもヘッダーからモーダルとして開きます。エージェントの返信は JSON に直接書き込まれるので、スレッドをリフレッシュするか開き直せば表示されます。

## ハイライト

- **blob にひも付いた「レビュー済み」マークと HEAD ピーク。** ファイルヘッダーをクリックするとレビュー済みにマークされます (同時に折りたたまれます)。マークはマーク時点のそのファイルの blob SHA にひも付くので、後から *1 つの* ファイルに触れる push があってもそのファイルのマークだけが無効化され、触れられていないファイルはすべて緑のまま残ります。コミットごとのビューからのマーク付けは「以降に変更がない」場合に限定されるため、見ていない内容にサインオフしてしまうことはありません。このゲートが発動したときは、`p` でコミットビューを離れずに HEAD でのファイルをピークできます。カーソル行を中心とした集中ウィンドウが、コミットから HEAD への差分をたどって表示されるので、間に入った編集でカーソルがずれることはありません。

- **すべての差分で重要度順に並ぶファイル。** 全体差分もコミットごとの差分も、変更セットにおける中心性でファイルを並べ替えます。被参照数 (この 1 つを *他のどれだけの変更済みファイル* が import しているか)、次にステータス (modified が added より前、added が removed より前)、次にソース優先 (ソースファイルがテスト・ドキュメント・フィクスチャ・changeset・JSON / YAML / TOML やロックファイルなどの設定/データファイルより前)、最後にパスの順です。アルファベット順のノイズではなく、まず負荷の中心となる編集に着地します。[pi-slopchop](https://github.com/robzolkos/pi-slopchop) の PR #2 から移植しました。

- **同梱スキルによる LLM-in-the-loop。** `skills/slop-review/SKILL.md` にある Claude Code スキルにより、エージェントは `.reviews/` の JSON を直接読み書きすることで、レビュアー (インラインコメントを残す) またはレビュイー (オープンなスレッドに対応し、ソースを編集し、返信する) を演じられます。HTTP 連携は不要です。

- **3 つの差分モード、1 枚のページ。** 全体差分 (ベースに対する累積)、任意の単一コミット、またはローカルの作業コピー差分。`Shift+←` / `Shift+→` でそれらを行き来でき、コメントは 3 つすべてで機能します。

- **複数検索のパーキングを備えたファイル横断シンボルパネル。** 差分内の任意の識別子をダブルクリックすると、変更済みファイル全体での出現箇所が一覧表示され、アクティブな行がその場でハイライトされます。2 つ目のシンボルを開くと 1 つ目は右端のストリップにパークされ、マッチ一覧とジャンプ履歴が保持されるので、コンテキストを失わずに並行する検索の間をピボットできます。Esc でパーク、パークされたストリップをクリックで復元します。

- **コンテキスト対応のヒントバーを備えた Vim キーバインド。** 1 文字の動詞でキーボードから離れずに行単位のアクション (コメント、コピー、ディープリンク、削除) を駆動します。which-key ヒントバーは最初のキー押下で現れ、状態が変わるたびに再描画され、現在のカーソル行とモードで有効なキーだけを表示します。隠れたヒントは厳密に no-op なので、バーが死んだキーを宣伝することはありません。

- **Carbonyl によるターミナル限定レビュー。** `--carbonyl` (短縮: `-c`) は、ターミナルに描画する Chromium フォークである [Carbonyl](https://github.com/fathyb/carbonyl) を通じて差分 UI を TTY にそのまま描画します。これによりループ全体がエディターやエージェントの隣の 1 ペインに収まり、ブラウザもコンテキストスイッチも不要です。すべてのキーバインドが引き継がれます (Carbonyl が剥がすわずかな修飾キーのコードは shim がカバーします)。[Carbonyl 統合](#carbonyl-統合)を参照してください。

- **一方向の GitHub レビュースレッド同期。** `slop-review --sync` は現在のブランチの GitHub PR から *未解決の* レビュースレッドを引き込み、全体差分上のローカルスレッドにします。各 GitHub の作者は保持されます。再実行すると GitHub をミラーします。新しい返信が流れ込み、GitHub 上で解決されたスレッドはローカルで削除され、あなたがローカルで編集 / 返信 / 解決したスレッドにはフラグが立つので、あなたの編集はそのまま残ります。新しい GitHub の返信は引き続き追記されますが、あなたの作業が上書きされたり並べ替えられたりすることはありません。[GitHub レビュースレッド同期](#github-レビュースレッド同期)を参照してください。

## はじめに

```bash
cd /path/to/your-feature-branch
npx slop-review
```

cwd が自動的にレビュー対象としてブートストラップされ、サーバーは空いているポート (範囲 9410-9419、それから任意の空きポート) を選び、ブラウザが開きます。スレッドは `<repo>/.reviews/` に置かれます。ローカル限定に保ちたい場合は、そのリポジトリの `.gitignore` に追加してください。

すべてのフラグは任意です:

| フラグ        | エイリアス | 引数       | 説明                                                                                                          |
|--------------|-------|------------|---------------------------------------------------------------------------------------------------------------|
| `--port`     | `-p`  | `<n>`      | バインドするポート。デフォルト: `9410-9419` で最初に空いているもの、それから任意の空きポート                  |
| `--host`     |       | `<h>`      | バインドするホスト名。デフォルト `0.0.0.0`                                                                     |
| `--no-open`  |       |            | ブラウザを自動で開かない                                                                                      |
| `--carbonyl` | `-c`  | `[<path>]` | [Carbonyl](#carbonyl-統合) ターミナルブラウザで開く。引数なしでは `PATH` から `carbonyl` を解決、またはバイナリ / ディレクトリを渡す |
| `--sync`     | `-s`  |            | 未解決の GitHub PR レビュースレッドをローカルスレッドにミラーしてから終了する。`gh` が必要。[sync](#github-レビュースレッド同期) を参照 |
| `--browser`  | `-b`  |            | `--sync` の後に連鎖させ、同期完了後にデフォルトのブラウザで UI を開く                                          |
| `--threads`  | `-t`  |            | 同期せずにスレッドウォーク (全体差分、最初の未解決スレッドを表示) に直接入る                                   |
| `--overview` | `-o`  |            | ブランチ概要をターミナルで生成 (generator と任意の追加指示を選択) してから、その概要を開いた状態で UI を起動する。対話可能なターミナルが必要 |
| `--agent`    | `-a`  | `<name>`   | generator (`codex`、`claude`、`opencode`) を選択せずに名前で指定する。繰り返し指定 / カンマ区切り可。`--overview` を含意し、両方のプロンプトを省略するため TTY 不要 |
| `--prompt`   | `-P`  | `<text>`   | generator への追加指示。例: `-P '英語と日本語の両方で'`。`--overview` を含意し、追加指示のプロンプトを置き換える (`-p` は `--port` なので大文字) |
| `--detach`   | `-d`  |            | サーバーをバックグラウンドプロセスに引き渡し、応答を確認したら終了する。UI は起動したままシェルに戻る。pid を表示。`--carbonyl` とは併用不可 |
| `--kill`     | `-k`  |            | このリポジトリで動いているサーバーを停止して終了する (起動はしない)。停止対象がなければ 0 で終了              |
| `--help`     | `-h`  |            | ヘルプを表示                                                                                                  |

`--sync` は、`--browser`、`--carbonyl`、`--threads` を連鎖させない限りミラー後に終了します。これらを連鎖させると UI が開き、5 分ごとに再同期し続けます。`--threads` は同期せずに同じレジューム画面に到達します。

前提条件: Node ≥ 20、`PATH` 上の `git`、Overview 生成時は Python 3。ランタイム依存はありません。サーバーは `node:http` + 標準ライブラリのみなので、`npx slop-review` は推移的なパッケージを一切引き込みません。

Overview モーダルは、同梱の `explain-diff-html` skill を `codex exec`、`claude`、または `opencode run` で実行し、背景、直感的な説明、コード解説、必要に応じた図、インタラクティブなクイズを含む自己完結型 HTML を生成します。生成ツールは複数選択でき、選んだ CLI を並行実行した後、Overview ヘッダーのタブで結果を切り替えられます。「英語と日本語の両方で説明して」のような追加指示も入力でき、skill の多言語表示を利用できます。生成 HTML は generator ごとに `.reviews/` にキャッシュされ、sandbox 化された frame 内に表示されます。

同じ生成を UI なしでターミナルから実行することもできます。`slop-review --overview` (`-o`) は利用可能なエージェント CLI を検出し、チェックボックスの選択 (space で切り替え、`a` で全選択) と任意の追加指示の入力を提示し、選択した generator をライブ進捗付きで実行してから、Overview モーダルを開いた状態でアプリを起動します。起動フラグ (`--carbonyl`、`--port`、`--no-open` など) と組み合わせられます。

`--agent` (`-a`) で generator を指定すると両方のプロンプトを省略し、完全に非対話で実行されます。TTY が不要なので、シェル関数やスクリプトの中に組み込めます。

```bash
slop-review -o -a opencode              # generator 1 つ、プロンプトなし
slop-review -a codex,claude --no-open   # generator 2 つ。-a は -o を含意する
```

未知の名前や `PATH` に見つからないエージェントは、生成を始める前にエラーになります。

`--prompt` (`-P`) は追加指示プロンプトのフラグ版です。モーダルと同じ項目で、指定した言語や注目してほしい箇所が反映されるため、スクリプト実行でも generator を誘導できます。

```bash
slop-review -o -a opencode -P '英語と日本語の両方で'
slop-review -P 'マイグレーションを中心に' -a codex   # 選択は -a、追加指示は -P で省略
```

追加指示は 2000 文字までです (超過分は通知付きで切り詰められます)。`-P` を渡すと `-o` も含意されます。対話実行では追加指示のプロンプトだけが置き換えられ、generator の選択画面は表示されます。`-p` は `--port` なので、大文字であることに注意してください。

概要が表示された後もそのまま処理を続けたい場合は `--detach` (`-d`) を付けます。サーバーをバックグラウンドプロセスに引き渡してブラウザを開き、プロンプトを返すので、概要を読んでいる間に時間のかかるコマンドを同じチェーンで続けられます。

```bash
slop-review -o -a opencode -d && your-long-review-command
```

UI を閉じるときに使う pid が表示されます。`--detach` は `--port`、`--host`、`--threads`、`--sync`、`--no-open` (ブラウザを開かずバックグラウンドで待機) と組み合わせられますが、起動元のターミナルを必要とする `--carbonyl` とは併用できません。

停止は `--kill` (`-k`) で行うので、pid を探す必要はありません。

```bash
slop-review -k          # このリポジトリのサーバーを停止して終了
```

現在のリポジトリで動いている slop-review サーバー (バックグラウンドのものも、別のターミナルに残っているフォアグラウンドのものも) をすべて停止します。停止対象がなくても 0 で終了するため、スクリプトの最後に無条件に呼んでも問題ありません。サーバーは `<repo>/.reviews/_servers.json` に記録されるので `-k` はリポジトリ単位で動作し、別のチェックアウトのサーバーには触れません。シグナルを送る前に実際のプロセスと照合する (SIGTERM の後、3 秒待って SIGKILL) ため、再利用された pid を誤って停止することはなく、後片付けせずに死んだエントリは削除されるだけです。

状態は `~/.config/slop-review/state.json` に置かれます (`XDG_CONFIG_HOME` を尊重)。スキーマバージョンと、リポジトリごとの UI 状態 (最後のビュー + スレッドレジューム用のカーソル) が含まれます。

## 想定される挙動

GitHub レビューの操作感覚を意外に思わせるかもしれない、意図的な挙動がいくつかあります。

### 起動時の着地点

コールド起動はまずこのブランチの最後のビューのレジュームを試み、それからコミットごとのデフォルトにフォールバックします:

| シナリオ                                              | 着地点                          |
|-------------------------------------------------------|---------------------------------|
| URL が sha または `local` を明示的に指定               | 解決できれば尊重 (できなければ以下にフォールスルー) |
| 保存された最後のビューが存在し、まだ解決できる         | そのビューをレジューム           |
| フィーチャーブランチ、ベースより先行したコミットあり   | 最初のコミット (ブランチ内で最も古い) |
| `main`/`master` 上、先行コミットなし                   | 最新のコミット                   |
| `main`/`master` 上、先行コミットなし、ローカル編集あり | ローカルビュー                   |
| 空ブランチ (コミットがまったくない)                    | 全体差分 (退化時のフォールバック) |

理由: フィーチャーブランチのレビューはベースから前へ歩むので、最初のコミットが自然な入口です。ベース上のパスは、リポジトリ履歴全体を合成しうる空ツリーの merge-base フォールバックを使い、そこでは最新のコミットがプロジェクトの黎明より優先されます。全体差分は常に `Shift+→` 1 回で到達できます。

### レジューム

各ナビゲーション (Shift+←/→、ナビボタン、または新しいハッシュ URL) は、現在のビューを `state.config.repo_ui_state.<repoId>.last_view:<branchId>` の下に `full`、`local`、または `commit:<sha>` としてスタンプします。次のコールド起動はそれをリハイドレートします。ただし保存されたコミットがもはや存在しない (force-push、rebase、GC された sha) 場合は、上記のスマートデフォルトの表が発動します。ブランチごとのスコープにより、ブランチを切り替えても誤った sha を持ち越すことはありません。

## Carbonyl 統合

slop-review は任意のブラウザで動作し、さらに [Carbonyl](https://github.com/fathyb/carbonyl) (TTY に描画する Chromium ベースのブラウザ) を通じてターミナル内で完全に動作します。`--carbonyl` はデフォルトの GUI ブラウザの代わりにそれを起動します:

```bash
# 一度だけインストール (macOS、genkio/tap homebrew tap 経由のビルド済みバイナリ):
brew install genkio/tap/carbonyl

# 起動ごとにオプトイン:
slop-review --carbonyl
```

引数なしの `--carbonyl` は `PATH` から `carbonyl` バイナリを解決します (brew のインストールが配置する場所)。dev ビルドやカスタムのインストール先には、バイナリかそれを含むディレクトリを渡します:

```bash
slop-review --carbonyl ~/code/carbonyl/dist
slop-review --carbonyl ~/code/carbonyl/dist/carbonyl
```

Carbonyl は slop-review のターミナルを継承するので、ウィンドウ切り替えのない 1 ペインのループになります。Carbonyl を終了する (Ctrl+C) と、サーバーも一緒に終了します。

### キーバインド

差分ビューは完全にキーボード駆動です。同じバインドは通常のブラウザでも Carbonyl でも機能しますが、以下に注記する 2 つの修飾キーのコードは例外です。Carbonyl の Chromium フォークは keydown を転送する前に Ctrl/Cmd/Shift を剥がすため、修飾キーを使うバインドには代替が必要です。

| キー                   | アクション                                          | Carbonyl                       |
|-----------------------|----------------------------------------------------|--------------------------------|
| `j` / `k`             | カーソルを 1 行下 / 上に移動                        | yes                            |
| `J` / `K`             | カーソルを 5 行下 / 上に移動                        | yes                            |
| `gg` / `G`            | カーソルを diff の先頭 / 末尾の行に移動              | yes                            |
| `c` / `C`             | 新側 / 旧側の行でコメントエディターを開く           | yes                            |
| `v` / `V`             | ビジュアル行選択を開始 (新 / 旧側)                  | yes                            |
| `y` / `Y`             | カーソル行への `path:line` 参照をコピー (新 / 旧側) | yes                            |
| `o` / `O`             | カーソル行を forge で開く (新 / 旧側)               | yes                            |
| `r`                   | カーソル行のファイルのレビュー済みをトグル          | yes                            |
| `n` / `N`             | ビュー内の次 / 前のスレッドへジャンプ               | yes                            |
| `d`                   | カーソル下のスレッドを削除                          | yes                            |
| `p`                   | カーソル行の HEAD をピーク (コミットビューのみ)     | yes                            |
| `e`                   | カーソルの hunk 周辺のコンテキスト行を展開          | yes                            |
| `Enter`               | ビジュアル行選択を確定 / モーダルを確認             | yes                            |
| `Escape`              | 選択をキャンセル、パネルを最小化、モーダルを閉じる  | yes                            |
| `Backspace`           | アクティブなシンボルパネルのジャンプスタックのフレームをポップ | yes                  |
| `Cmd/Ctrl+Enter`      | コメントエディターを送信                            | 代わりに `;;` を使う           |
| `Shift+←` / `Shift+→` | 前 / 次のコミットへ移動 (またはローカル / 全体)     | `‹` / `›` ナビボタンを使う     |
| `←` / `→`             | スレッドモーダル内で前 / 次のスレッド               | yes                            |

`;;` (エディターにフォーカスがある状態で 400ms 以内のセミコロン 2 回) は `public/carbonyl-key-shim.js` が処理します。ダブルタップを検出し、最初の `;` を textarea から取り除き、合成された `Ctrl+Enter` をディスパッチして、既存の送信ハンドラー (`metaKey` または `ctrlKey` 付きの `Enter` をキーにしている) がそのまま発火するようにします。shim は無条件で読み込まれますが、Carbonyl の修飾キーが剥がされたイベントシグネチャでのみ発火するので、通常のブラウザでは no-op です。

コメント本文にリテラルの `;;` を入れるには、2 文字の間を 400ms 超で空ける (またはスペースを入れて `; ;` と打ってから編集で消す) ようにします。

## GitHub レビュースレッド同期

`slop-review --sync` は一回限り・一方向のミラーです。ブランチの GitHub PR から **未解決の** レビュースレッドをローカルスレッドに引き込み、それから終了します (サーバーもブラウザもなし)。認証とデータには `gh` CLI を使うので (GraphQL。GitHub がスレッドの *resolved* 状態を公開している唯一の場所)、`gh` がインストール・ログイン済みである必要があります。GitHub 以外の origin や、オープンな PR のないブランチでは何もしません。

```bash
slop-review --sync
```

セマンティクス:

- **アンカリング。** GitHub のレビュースレッドは PR の「Files」タブに存在するので、slop の **全体差分** (`view: "full"`) に着地します。GitHub の `RIGHT` / `LEFT` は slop の `new` / `old` にマッピングされ、複数行の範囲は保持されます。ファイルレベルのコメント (行アンカーなし) はスキップとして報告されます。
- **著者。** 同期されたコメントは GitHub の作者のログイン名を `user` として保持し、スレッドには **GitHub** バッジが表示され、各コメントのタイムスタンプは GitHub 上のオリジナルへリンクします。
- **再実行時のミラー。** 各同期は既存の同期済みスレッドをリフレッシュし (新しい返信が現れる)、GitHub 上で解決されたローカルスレッドを **削除** し、新たにオープンされたものを **作成** します。
- **ローカルの編集が優先。** 同期済みスレッドのコメントを編集・返信・削除したり、スレッドを解決したりすると `locally_modified` のフラグが立ちます。以降のすべての同期はあなたの編集に手を触れず、新しい GitHub の返信を **追記** するだけです。あなたの作業を上書きしたり並べ替えたりすることはありません。バッジは色がくすんで、乖離したことを示します。
- **一方向。** 同期が GitHub に書き戻すことはありません。
- **そのままレビューに入る。** `--browser` または `--carbonyl` を連鎖させる (例: `slop-review --sync --browser`) と、同期完了時に UI が起動し、全体差分に着地して最初の未解決スレッドのモーダルが開いた状態になります。素の `slop-review --sync` はサマリーを表示して終了するだけです。
- **開いている間もミラーし続ける。** `--sync` が UI を開く (`--browser` / `--carbonyl` / `--threads` と連鎖) と、サーバーは 5 分ごとに GitHub から再同期するので、新しい返信や解決が流れ込み続けます。差分ヘッダーの **「Synced …」** バッジは最後の引き込みが着地した時刻を示します (carbonyl でも描画されます)。引き込みが失敗すると **「Sync failed」** が表示されます。ループはサーバープロセス内で動くので、slop-review を終了する (ターミナルまたは carbonyl ペインで Ctrl-C) と引き込みも一緒に止まります。ページはスレッドをライブリロードしないので、バックグラウンド同期がスレッドを変更すると、バッジに **「· N behind」** (アンバー) が追記され、手動リロードの価値があることを伝えます。リロードかナビゲーションでクリアされます。

各実行はサマリーを表示します: 作成 / 更新 / 削除 / スキップ、そして GitHub の未解決の合計数。

## AI エージェント連携

slop-review は `skills/slop-review/SKILL.md` に Claude Code スキルを同梱しており、エージェントにスレッドを読むこと、レビュアーとしてコメントを残すこと、レビュイーとしてオープンなスレッドに対応することを教えます。`.reviews/` の JSON 上で直接機能し、HTTP API も動作中のサーバーも不要です。

開発者または LLM のどちらかが演じる 2 つの役割:

- **レビュアー** - 差分の行にインラインコメント / 質問を残す。
- **レビュイー** - ソースコードを編集し返信を追記することでコメントに対応する。

### インストール

[`skills`](https://www.npmjs.com/package/skills) npm パッケージ (Vercel Labs) 経由:

```bash
npx skills add genkio/slop-review
```

これでお使いのエージェント CLI 向けに `SKILL.md` が所定の場所にコピーされます (Claude Code: `~/.claude/skills/slop-review/SKILL.md`)。あとは自然にプロンプトを出すだけです。*「この slop-review ブランチのレビュアーとして振る舞って」*、*「未解決の slop-review スレッドに対応して」* と書けば、LLM が自動検出で拾い上げます。

### コントリビューター向けインストール (ホットイテレーション)

スキル自体を編集する場合は、`npx skills add` を再実行しなくても変更が反映されるようシンボリックリンクを張ります:

```bash
mkdir -p ~/.claude/skills
ln -sfn "$PWD/skills/slop-review" ~/.claude/skills/slop-review
```

このチェックアウト内の `skills/slop-review/SKILL.md` への編集が、次のプロンプトでライブになります。削除は `rm ~/.claude/skills/slop-review` で。(以前に `npx skills add genkio/slop-review` を実行したことがある場合は、まずインストール先パスの実ディレクトリを `rm -rf` してください。)

## 開発

```bash
git clone <this-repo> && cd slop-review
```

依存なし。HTTP レイヤー (`server/http.js`) は、ルーティング・JSON・静的ファイルのための `node:http` をラップした小さな自前の薄いラッパーです。変更する場合は、リクエストの全面を手動で動かして確認してください。`npm test` がカバーするのは diff/state ロジックのみです。フロントエンド (`public/**`) の編集はハードリフレッシュだけで済みます。

外部リポジトリに対して実際の `npx slop-review` フローをテストする:

```bash
cd /path/to/slop-review
npm link              # `slop-review` がこのチェックアウトを指すようになる
cd /some/target/repo
slop-review           # cwd のリポジトリに対してローカルコードを実行する

# または直接実行
node /path/to/slop-review/bin/slop-review.js
```
